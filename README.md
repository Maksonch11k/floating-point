## Что реализовано

В рамках работы была разрботана программа для выполнения арифметических операций над числами с плавающей точкой в соответсвии со стандартом IEEE-754. Все вычисления производятся с использованием целочисленных типов данных

*   **Поддерживаемые форматы:**
    *   `h` — половинная точность (half-precision), 16 бит
    *   `s` — одинарная точность (single-precision), 32 бита
*   **Реализованные операции:**
    *   Базовые арифметические операции: сложение (`+`) вычитание (`-`) умножение (`*`) деление (`/`)
    *   Составные операции: `mad` (multiply-then-add) и `fma` (fused-multiply-add)
*   **Режимы округления:**
    *   `0` — к нулю (toward zero)
    *   `1` — к ближайшему чётному (to nearest, ties to even)
    *   `2` — к положительной бесконечности (to positive infinity)
    *   `3` — к отрицательной бесконечности (to negative infinity)
*   **Специальные значения:** Корректно обрабатываются `NaN` `+inf` `-inf` а также положительный и отрицательный нули
*   **Ввод и вывод:**
    *   Аргументы парсятся из командной строки
    *   Результат выводится в стандартный ввод в формате шестнадцатеричной показательной нотации как того требует задание

# Описание:

### Общая структура проекта

Проект разделён на несколько логических частей для лучшей организации кода

1.  **`uint128.h`**: В этом файле реализованы пользовательские 128-битные целочисленные типы (`uint128_t` и `int128_t`). это реализовано так как по условию задачи запрещено использовать встроенные типы с плавающей точкой а для промежуточных вычислений (например при умножении мантисс) требуется точность превышающая 64 бита
2.  **`floating.h` / `floating.cpp`**: Здесь сосредоточена основная логика. Класс `fp_value` реализует представление числа с плавающей точкой. в этих файлах реализованы конструктор для парсинга битового представления числа перегруженные арифметические операторы функции `fma`/`mad` и вспомогательные функции для округления и создания специальных значений
3.  **`main.cpp`**: Этот файл отвечает за взаимодействие с пользователем. он парсит аргументы командной строки определяет необходимую операцию создает экземпляры класса `fp_value` и вызывает соответствующие методы для вычисления и вывода результата

### Хранение чисел и специальные значения

Центральным элементом является класс `fp_value`. число с плавающей точкой хранится не как единое целое а в разобранном виде что упрощает выполнение арифметических операций

*   **Поля класса:**
    *   `raw_bits`: Исходное битовое представлене числа
    *   `is_negative`: Булев флаг для знака
    *   `exponent`: Хранит смещенный порядок числа
    *   `mantissa`: Целочисленное представление мантиссы включая скрытый бит (для нормализованных чисел)
    *   `exponent_width`, `mantissa_width`: Ширина полей для данного формата (`half` или `single`)
    *   Булевы флаги для специальных значений: `is_nan` `is_positive_infinity` `is_negative_infinity` `is_positive_zero` `is_negative_zero` `is_subnormal`

Конструктор `fp_value` принимает 64-битное целое `initial_bits` и используя битовые маски и сдвиги извлекает знак порядок (экспоненту) и мантиссу

*   **Нормализация:** если число является нормализованным к его мантиссе добавляется скрытый бит (`1LL << mantissa_width`). Если число субнормальное (экспонента равна `0` а мантисса не `0`) оно приводится к нормализованному виду путем сдвига мантиссы влево до тех пор пока старший бит не станет единицей. при этом значение экспоненты корректируется на величину сдвига
*   **Специальные значения:** Если поле экспоненты заполнено единицами конструктор проверяет мантиссу. если она не равна нулю устанавливается флаг `is_nan`. в противном случае в зависимости от знака устанавливаются флаги `is_positive_infinity` или `is_negative_infinity`. Нули определяются по нулевым значениям экспоненты и мантиссы

### Детальное описание 128-битной арифметики (`uint128.h`)

Поскольку стандарт C++ не предоставляет встроенного 128-битного целочисленого типа а для промежуточных вычислений (например умножение двух 64-битных мантисс) требуется большая разрядность был создан собственный класс `uint128_t`

**Структура и хранение**
Класс `uint128_t` представляет 128-битное беззнаковое целое число состоящее из двух 64-битных полей
*   `uint64_t high`: хранит старшие 64 бита
*   `uint64_t low`: хранит младшие 64 бита

**Реализация операций**
*   **Сложение (`operator+`):** Сложение реализовано покомпонентно. сначала складываются младшие части (`low`). Если происходит переполнение (что определяется по тому что результат сложения меньше одного из слагаемых) это означает что возник перенс в старший разряд. в этом случае к результату сложения старших частей (`high`) добавляется единица

    ```cpp
    uint64_t new_low = low + other.low;
    uint64_t new_high = high + other.high + (new_low < low);
    ```

*   **Вычитание (`operator-`):** Реализовано аналогично сложению но с учётом заёма из старшего разряда. если при вычитании `low` частей результат оказывается больше уменьшаемого значит произошёл заём. в этом случае из старшей части (`high`) вычитается единица

*   **Умножение (`multiply_u64`):** для умножения двух 64-битных чисел с получением 128-битного результата используется метод аналогичный "школьному" умножению в столбик. Каждый 64-битный множитель (`a` и `b`) разбивается на две 32-битные части (старшую и младшую): `a = a1*2^32 + a0` `b = b1*2^32 + b0`.
    Произведение `a*b` раскладывается на четыре 64-битных произведения
    1.  `p0 = a0 * b0`
    2.  `p1 = a0 * b1`
    3.  `p2 = a1 * b0`
    4.  `p3 = a1 * b1`

    Итоговый 128-битный результат собирается из этих частей с учётом сдвигов:
    `result = p0 + (p1 << 32) + (p2 << 32) + (p3 << 64)`.
    В коде это реализовано через акуратное сложение частей и обработку переносов между ними

*   **Битовые сдвиги (`operator<<`, `operator>>`):** Сдвиги на величину меньшую 64 требуют перемещения битов между полями `high` и `low`. например при сдвиге влево (`<<`) старшие биты из `low` становятся младшими битами `high`. при сдвиге на 64 и более бита операция упрощается до перемещения или обнуления целых 64-битных полей

На базе `uint128_t` построен знаковый тип `int128_t` который хранит значение в дополнительном коде и реализует операции с учётом знака

### Детальная реализация арифметических операций

Каждая операция следует общему алгоритму
1.  Обработка специальных случаев (`NaN` бесконечности нули)
2.  Декомпозиция операндов на знак экспоненту и мантиссу
3.  Выполнение целочисленной арифметики над мантиссами и экспонентами
4.  Нормализация и округление результата
5.  Сборка итогового битового представления

**1. Сложение (`operator+`):**
1.  **Выравнивание порядков:** Это ключевой этап. нельзя складывать мантиссы чисел с разной экспонентой. Мантисса числа с *меньшей* экспонентой сдвигается вправо на величину разницы экспонент. этот сдвиг эфективно делит число на степень двойки приводя его к той же экспоненте что и у второго операнда. Потерянные при сдвиге биты сохраняются для последующего округления
2.  **Сложение/вычитание мантисс:** Выровненные мантиссы складываются или вычитаются (в зависимости от знаков операндов). для этой операции используется `int128_t` чтобы корректно обработать знак результата
3.  **Нормализация результата**
    *   **Массивная аннуляция:** если вычитались близкие по значению числа результат может иметь много ведущих нулей (например `1.0001 - 1.0000 = 0.0001`). в этом случае мантисса сдвигается влево до тех пор пока старший бит не станет единицей. за каждый сдвиг экспонента уменьшается на единицу
    *   **Переполнение:** Если сумма мантисс привела к переносу бита за пределы разрядной сетки (например `1.1_bin + 1.1_bin = 11.0_bin`) мантисса сдвигается вправо на один бит а экспонента увеличивается на единицу

**2. Умножение (`operator*`):**
1.  **Экспонента:** Порядки исходных чисел складываются. поскольку в каждом из них хранится смещение (`bias`) итоговая экспонента вычисляется как `E_res = (E1_stored - bias) + (E2_stored - bias)`. в коде это реализовано через сложение "чистых" экспонент с последующим добавлением смещения
2.  **Мантисса:** Мантиссы (включая скрытый бит) перемножаются с помощью `uint128_t::multiply_u64`. результат занимает до `2 * (mantissa_width + 1)` бит
3.  **Нормализация:** Произведение двух нормализованных чисел (`1.xxxx...`) всегда лежит в диапазоне `[1.0, 4.0)`. это означает что для нормализации результата потребуется не более одного сдвига вправо с сопутсвующей инкрементацией экспоненты

**3. Fused Multiply-Add (`fma`):**
Главное преимущество `fma` — **единственное округление в конце**
1.  **Умножение:** `a * b` вычисляется с полной удвоенной точностью. Промежуточный результат (мантисса и экспонента) не округляется
2.  **Выравнивание:** Операнд `c` выравнивается по порядку полученному на шаге 1. его мантисса сдвигается вправо или влево на необходимое число позиций
3.  **Сложение:** Выровненная мантисса `c` складывается с произведением `a*b` с полной точностью
4.  **Нормализация и округление:** Только теперь итоговая сумма нормализуется и округляется до целевого формата. это позволяет избежать потери точности которая произошла бы если бы результат `a*b` был округлен перед сложением с `c`

### Детальное описание механизма округления

После арифметических операций и нормализации итоговая мантисса часто содержит больше битов чем может поместиться в целевой формат. Механизм округления решает следует ли отбросить лишние биты (округление вниз) или увеличить итоговую мантиссу на единицу (округление вверх)

Для этого анализируются отбрасываемые биты. вместо того чтобы хранить их все используется стандартный и эффективный подход с тремя битами

*   **LSB (Least Significant Bit):** Младший значащий бит мантиссы который сохраняется. он нужен для режима "к ближайшему чётному"
*   **Guard bit (G):** Первый (старший) из отбрасываемых битов. если G=1 значит отбрасываемая часть больше или равна половине младшего разряда сохраняемой части
*   **Sticky bit (S):** Логическое "или" всех остальных отбрасываемых битов. если S=1 значит отбрасываемая часть строго больше половины младшего разряда

**Пример**
допустим нам нужно округлить двоичное число `1.1011 101` до 4 знаков после точки
*   Сохраняемая часть: `1.1011`. Её **LSB** = `1`
*   Отбрасываемые биты: `101`
*   **Guard bit (G)** = `1` (первый из `101`)
*   Остальные биты: `01`. **Sticky bit (S)** = `0 OR 1` = `1`

Теперь применяем правила для разных режимов

1.  **`to_zero` (к нулю):** Всегда округляет вниз. просто отбрасываем `101`. Результат: `1.1011`
2.  **`to_positive_infinity` (к +бесконечности):** Если число положительное и отбрасываемая часть не равна нулю (т.е. G=1 или S=1) округляем вверх. В нашем примере G=1 S=1 так что округляем вверх: `1.1011 + 0.0001 = 1.1100`
3.  **`to_negative_infinity` (к -бесконечности):** Если число отрицателное и отбрасываемая часть не равна нулю округляем "вниз" (т.е. увеличиваем по модулю). Для `-1.1011101` результатом будет `-1.1100`
4.  **`to_nearest_even` (к ближайшему чётному)**
    *   Если G=0 отбрасываемая часть < 0.5. Округляем вниз
    *   Если G=1 и S=1 отбрасываемая часть > 0.5. Округляем вверх. в нашем примере `G=1 S=1` округляем до `1.1100`
    *   **Случай "ровно посередине" (tie-breaking):** Если G=1 и S=0. В этом случае мы округляем к тому значению у которого LSB равен 0 (т.е. к чётному)
        *   Если бы у нас было `1.1011 100` (LSB=1 G=1 S=0) мы бы округлили вверх до `1.1100` чтобы последний бит стал чётным
        *   Если бы было `1.1010 100` (LSB=0 G=1 S=0) мы бы округлили вниз до `1.1010` так как последний бит уже чётный) мы бы округлили вниз до `1.1010` так как последний бит уже чётный
